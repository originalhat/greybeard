# Context

Knowledge that is **specific** to one app: how to start it, how to log in, what data exists, and what is already known to be odd. Lenses say where to look. Context saves each run from rediscovering the basics.

## Contents

| File | Purpose |
|------|---------|
| `APPS.md` | Per repo: launch, base URL, logins and roles, seed data, known quirks |

## Growing Context

A run that had to ask for something (a login, a seed command) or that reported a pre-existing quirk proposes the `APPS.md` line under the report's **Context** section. A human adds it. Runs do not edit this directory themselves.

Never put production credentials or real member data here. Local seed logins are fine.
