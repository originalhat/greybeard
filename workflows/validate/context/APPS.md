# Apps

One section per repo. Keep each entry to what a tester needs to get started and what not to report again.

## Format

```markdown
## {repo}

- **Launch:** {command or skill, and the base URL it serves}
- **Console / runner:** {how to open a local console, run a job, or tail the server log}
- **Outbound stubs:** {how email, SMS, and vendor calls are stubbed locally, and where to see what would have been sent}
- **Logins:** {role}: {local seed login, or where to find it}
- **Seed data:** {command to load it, and what useful records it creates}
- **Can't exercise locally:** {areas that need a vendor sandbox, a device, or data we don't have}
- **Known quirks:** {pre-existing behavior not worth reporting again, with the ticket ID if there is one}
```
